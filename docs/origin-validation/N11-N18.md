# Open Fufu — Origin Validation Coverage N11–N18

## Status and authority

This file is a continuation of [`../ORIGIN_VALIDATION_COVERAGE.md`](../ORIGIN_VALIDATION_COVERAGE.md) and uses the same canonical coverage model.

It owns **validation coverage/dependency tracing only** for N11–N18. Origin mechanics remain canonical in [`../ORIGIN_TRAIT_CATALOGUE.md`](../ORIGIN_TRAIT_CATALOGUE.md), and focused subsystem mechanics remain owned by their normal documents.

The relationship classes remain:

1. **Direct transformation** — the subsystem whose rule/value/permission/state the trait directly changes.
2. **Required integration seam** — trait-specific state/event flow crossing subsystem boundaries.
3. **External semantic dependency** — canonical state/mechanics the trait reads but does not own.
4. **Ordinary downstream consumption** — valid canonical state that ordinary consumers must already handle without redundant trait-specific implementations.

Negative traits additionally require explicit attention to **hard prohibitions, caps, admission rules, hard-zero transforms, and precedence**. A positive modifier, discount, grant, alternate route, or downstream consumer must not silently bypass a negative trait's canonical hard rule.

Mechanic-definition holes discovered here are blockers only. This file must not invent the missing gameplay rule.

# 1. N11–N18 coverage

## N11 — Absolute Territory

**Direct transformations / owners**

- Spatial FFY-event yield resolution.
- A qualifying FFY event located inside the relevant SAM Launcher area yields exactly `0 FFY` for the N11 holder.
- This is an explicit hard-zero of FFY yield, not an ordinary negative yield percentage.

**Required seams / dependencies**

- `qualifying positive FFY event -> canonical event location -> qualifying SAM-area membership -> ordinary FFY modifier ordering -> explicit N11 hard-zero`.
- The FFY owner already establishes that explicit hard-zero rules apply after ordinary structural transforms/yield percentages and the nonnegative clamp. N11 must therefore remain zero regardless of earlier positive/negative percentage modifiers.
- The event itself must remain a canonical event even when its FFY yield is zero unless the event owner explicitly says otherwise. N11 zeroes the FFY result; it does not retroactively erase the event identity, route stop, capture, or other non-FFY side effect.
- Non-spatial passive FFY sources must not be assigned an artificial location merely so N11 can zero them.

**Explicit interactions**

- `N11 + N04`: if a Mountain-located event is also inside a qualifying SAM area, N04's percentage transform resolves through the ordinary yield path and N11 then hard-zeroes the final FFY yield.
- `N11 + P14`: a Desert-located event can receive P14's positive spatial modifier and still end at exactly zero under N11 when it also qualifies for the SAM area.
- `N11 + P24`: Fort-area FFY bonuses cannot resurrect an event after N11's hard zero.
- `N11 + P40`: P40 changes the SAM's effective interception range. If N11's authored `SAM Launcher area` is canonically the effective SAM coverage/interception area, N11 must consume that same transformed geometry rather than a hidden baseline radius. Exact coverage waits on the affiliation/area blocker below.
- `N11 + P33`: a Train-triggered economic event at an owned City remains a Train event even if N11 reduces its FFY yield to zero. P33's separate Population grant is keyed from the Train event/City level and must not be erased merely because the FFY component was hard-zeroed.
- P05 and other Origin-created FFY events can only receive exact N11 expectations once those events expose a canonical event location; P05's existing location blocker therefore propagates into P05+N11 certification.

**Non-effects**

- N11 does not change SAM charges, interception behavior, structure cost, event family, event ownership, purchase prices, explicit FFY losses/penalties, or non-FFY event side effects.

**Blocker / mechanic-definition finding**

- The trait says `inside SAM Launcher area` but the inspected canonical material does not close **which SAM affiliation qualifies** (owned SAMs only, fixed-teammate SAMs, any friendly SAM, or another explicit relation) nor explicitly state whether the economic area is exactly the SAM's current effective interception radius after transformations such as P40. Exact spatial membership therefore cannot be certified without the canonical SAM-area ownership/geometry rule.

## N12 — Panzer Vor!

**Direct transformations / owners**

- Naval-unit build admission.
- The holder **cannot build Warships**.
- This is a hard Warship-construction prohibition, not a stat penalty and not inherently a prohibition on owning/using a Warship obtained through some future explicitly legal non-build path.

**Required seams / dependencies**

- `Warship build request -> unit/build legality -> N12 hard prohibition` before FFY/Population payment or construction begins.
- The prohibition must apply at every ordinary Warship-production entry point, including any active owned Port that would otherwise be allowed to construct the unit.
- Failed N12 build attempts must not consume FFY, Population, P21-like purchase entitlements, construction slots, or other transactional state.

**Explicit interactions**

- `N12 + P42`: P42's `0 FFY / 2,000 Available Population` purchase transform does not bypass N12. The Warship remains unbuildable, so no Population may be consumed.
- `N12 + P23`: P23's one-Warship cap/profile remains potentially inert because N12 prevents ordinary construction; the positive trait does not create an alternate construction path.
- `N12 + P22/P29/P30/P31`: rank, mobile-launcher, pirate-Warship, and enhanced-repair transformations do not override the build prohibition. If a future canonical scenario/grant path legally supplies a Warship, those traits may still transform that existing unit unless that future owner says otherwise.
- Ordinary Port existence/repair/Trade-Ship behavior remains legal; N12 forbids Warship construction, not Ports themselves.

**Non-effects**

- N12 does not forbid Ports, Trade Ships, Transports, strategic weapons from persistent Silos, or naval repair. It does not delete an already-existing Warship by itself.

## N13 — Beach Episode Gone Wrong

**Direct transformations / owners**

- Amphibious Transport landing Population resolution.
- `50%` of the Transport's carried Population dies when the N13 holder lands.
- The casualty is permanent Population loss; it is not FFY cost, temporary commitment, or a damage value on the Transport chassis.

**Required seams / dependencies**

- `active Transport carried Population -> arrival at canonical landing lifecycle point -> N13 landing casualty -> surviving committed Population -> ordinary local hostile/neutral territorial engagement` once the exact lifecycle order is canonically closed.
- The lost Population must leave Total Population and cannot later return through Transport abort/return handling.
- N13 must operate on the Transport's actual carried Population at the landing point, not the original embark commitment if another prior canonical event has already changed the carried amount.
- Transport destruction before landing remains ordinary full carried-Population loss and must not additionally apply an N13 landing loss to a landing that never occurred.
- Abort/return without landing remains the ordinary return-loss lifecycle; N13 must not fire solely because the vessel reached an owned return point.

**Explicit interactions**

- `N13 + P37`: P37's Fort grant occurs only after a successful amphibious landing establishes land ownership. N13 must affect the Population that is available to achieve that local ownership result; it cannot be evaluated after the Fort grant in a way that lets dead Population contribute to capture.
- `N13 + P32`: the armored/health-bearing Transport may survive attacks that would destroy an ordinary Transport, but when it actually reaches the canonical landing point N13 still applies to carried Population. Naval repair does not restore carried Population casualties.
- `N13 + P12`: faster Transport movement changes time-to-landing/exposure only; the landing-loss percentage remains `50%`.
- `N13 + N15/P37`: embarkation-cost transforms affect FFY at embark time and are independent from the later Population casualty.
- `N13 defender/attacker interactions with P47/N18/terrain`: after N13 establishes the surviving landing commitment, the ordinary territorial engagement consumes that resulting Population and all target-side capture rules normally.

**Non-effects**

- N13 does not alter Transport speed, health, active cap, embarkation legality/cost, target legality, territorial progress coefficients, or capture casualties after the survivors enter ordinary land engagement.

**Blocker / mechanic-definition finding**

- `50% ... dies when landing` does not yet identify one exact authoritative **landing lifecycle point/order** relative to arrival, creation of the local land commitment, first capture/settlement resolution, and successful-landing determination. Validation also needs the deterministic fixed-point/rounding rule when carried Population cannot be divided exactly in half. The naval/amphibious owner must close that generic landing-casualty contract rather than #31 guessing it.

## N14 — To Them Words Are Merely a Means to Deceive

**Direct transformations / owners**

- Trade-Ship first-hostile-capture owner-side FFY loss.
- When one of the holder's Trade Ships is **first captured by a hostile faction**, the original owner loses exactly that voyage's snapshotted `Vowner` once.
- Later recapture/re-capture of the same physical cargo does not repeat the N14 owner-side loss.

**Required seams / dependencies**

- `Trade voyage launch -> canonical Vowner snapshot -> physical Trade Ship/cargo identity -> first hostile capture transition -> N14 owner FFY debit exactly once`.
- The N14 loss is an explicit negative FFY transaction, not a positive FFY event. Ordinary positive-event yield modifiers must not multiply it merely because they affect the voyage's ordinary success payout.
- First capture still follows the ordinary cargo lifecycle: commercial completion is canceled, cargo stays physical, no captor piracy payout occurs until terminal delivery, and repeated ownership changes do not mint new N14 losses.
- Destruction before first hostile capture produces no N14 loss because the trigger never occurred.

**Explicit interactions**

- `N14 + N16`: explicitly canonical. On first hostile capture N14 applies `-Vowner` while N16 applies `+Vowner` once; the owner-side deltas cancel exactly without suppressing the physical capture/cargo lifecycle.
- `N14 + P06`: Trade Ship speed changes exposure/travel time but does not change a launch-time `Vowner` snapshot unless the eventual canonical Vowner formula explicitly includes a speed-dependent term.
- `N14 + P30`: P30 affects the hostile final holder's piracy payout and Warship behavior. It does not alter the original owner's one-time N14 loss merely because the captor later receives a transformed piracy payout.
- `N14 + P08/P14/P24/N04/N11`: exact expectations depend on the missing canonical Vowner definition. Validation must not infer which wartime/spatial/event modifiers are snapshotted into Vowner.

**Non-effects**

- N14 does not immediately pay the captor, change raw cargo, alter route selection, prevent recapture, or change the eventual terminal cargo payout owner/rules.

**Blocker / mechanic-definition finding**

- The Origin catalogue says N14/N16 use the canonical launch-time owner-side voyage value `Vowner` **defined by `FFY_ECONOMY.md`**, but the inspected FFY owner currently defines launch-time `rawCargo` and resolution-time payout behavior without actually defining `Vowner` or which modifiers/state are included in that snapshot. Exact N14/N16 certification is therefore blocked until the FFY owner specifies the `Vowner` formula and snapshot inputs.

## N15 — King's Ransom

**Direct transformations / owners**

- Transport embarkation transaction cost.
- Adds exactly `+500 FFY` to the holder's Transport embarkation cost on the dedicated embarkation-cost hook.

**Required seams / dependencies**

- `Transport embark request -> ordinary embark legality -> effective additive embark cost -> affordability -> atomic FFY payment -> Transport creation/Population commitment`.
- Baseline Transport embarkation cost is `0 FFY`, so N15 alone produces `500 FFY` before any other explicit embark-cost transform.
- The FFY is a cost/negative transaction; positive FFY-yield modifiers do not alter it.
- A failed/invalid embarkation must not consume the cost.

**Explicit interactions**

- `N15 + P37`: explicitly canonical additive hook. P37 contributes `+250 FFY`; N15 contributes `+500 FFY`; combined additional embarkation cost is exactly `+750 FFY` over baseline.
- `N15 + P32`: P32 changes legal embark source and Transport chassis; after an owned active Port passes legality, N15 still participates in the same effective embark cost.
- `N15 + P12/N13`: movement speed and later landing casualty do not change the embark-cost arithmetic.

**Non-effects**

- N15 does not change Transport Population commitment, movement speed, health, active cap, return loss, landing rules, or territorial engagement.

## N16 — Insurance Fraud

**Direct transformations / owners**

- Trade-voyage original-owner payout/loss inversion using the same launch-time `Vowner` snapshot as N14.
- Successful **uncaptured** owner completion replaces the ordinary owner payout with an FFY **loss of `Vowner`**.
- On the **first hostile capture**, the original owner instead receives `+Vowner` exactly once.

**Required seams / dependencies**

- `Trade voyage launch -> Vowner snapshot -> physical voyage identity -> terminal uncaptured completion OR first hostile capture`.
- Uncaptured completion must not both pay the ordinary commercial event and charge N16; N16 replaces the owner-side ordinary success result with the authored loss.
- The uncaptured loss is an explicit negative transaction, not a positive Naval/trade event whose own yield modifiers can amplify/reduce the debit.
- On first hostile capture, the one-time `+Vowner` owner-side result is distinct from the captor's later terminal piracy payout. Physical cargo remains in play under ordinary capture/recapture/delivery rules.
- Subsequent recaptures do not grant repeated `+Vowner` to the original owner.
- Destruction without an uncaptured success or first hostile capture produces neither branch unless another canonical rule says otherwise.

**Explicit interactions**

- `N16 + N14`: first-hostile-capture owner-side deltas cancel (`+Vowner` and `-Vowner`) exactly, while the captured cargo continues normally.
- `N16 + P30`: P30 may multiply the hostile final holder's piracy FFY; that terminal captor event is separate from the original owner's one-time N16 `+Vowner`.
- `N16 + P06`: speed changes voyage duration/exposure only and must not resnapshot `Vowner` in flight.
- `N16 + P08/P14/P24/N04/N11`: exact interaction values wait on the shared Vowner-definition blocker; no validator should guess whether resolution-time war/spatial modifiers are included in the launch snapshot.

**Non-effects**

- N16 does not change route selection, raw physical cargo, capture eligibility, cargo destruction, Warship pursuit, or who receives terminal captured-cargo payout.

**Shared blocker / mechanic-definition finding**

- Exact N16 certification shares N14's missing canonical `Vowner` definition in the FFY owner. The snapshot's formula and included/excluded modifier state must be explicit before owner-side success/capture deltas can have one authoritative expected value.

## N17 — I Can Cut It

**Direct transformations / owners**

- Canonical successful hostile territorial-capture structure resolver.
- N17 contributes a capture-disposition transformation: a structure that would otherwise proceed toward transfer is resolved as **`DESTROYED_ON_CAPTURE` instead of `STRUCTURE_TRANSFERRED`**.
- The territorial cell capture itself remains an ordinary successful capture unless some independent territorial-acquisition rule prevents it.

**Required seams / dependencies**

- `successful enemy-cell capture -> frozen StructureCaptureContext -> N17 TRANSFER→DESTROY disposition transform -> typed capture consequences -> atomic commit`.
- Capture-time destruction removes the physical structure and all structure-owned fields/services/charges/station/production state, but it is a distinct capture-resolution result rather than an ordinary combat kill.
- Effects keyed specifically to `STRUCTURE_TRANSFERRED` must not fire. Effects deliberately keyed to `STRUCTURE_DESTROYED_ON_CAPTURE` may do so if a current/future canonical rule defines them.
- No `CAPTURE_TRANSFER` admission or incoming ownership-slot reservation is needed after N17 has already resolved the disposition to destruction.
- The rule applies only when the **N17 holder is the captor**. It does not cause N17-owned structures to self-destruct merely because an enemy captures them.

**Explicit interactions**

- `N17 + P05`: P05 consumes `STRUCTURE_TRANSFERRED`; N17 produces `DESTROYED_ON_CAPTURE`, so P05 does not fire.
- `N17 + P34`: a Factory destroyed on capture never transfers and therefore never acquires P34 conquered-Factory provenance.
- `N17 + N07`: N17 resolves the incoming structure to destruction before transfer admission, so N07 overflow admission is not needed for that capture path. N07 still governs builds/grants/other transfers.
- `N17 + P49/P50/P51`: destroying an Observation Post/Fort/Command Post removes the structure and its transformed effective fields rather than transferring those fields to the new territorial owner.
- `N17 attacker -> P47 defender`: if the captured structure sits on a P47 defender's Marsh cell, P47's post-capture attacker casualty still keys from the successful cell capture; N17 independently resolves the structure as destroyed on capture.
- `N17 attacker -> P38 defender`: P38 may preserve an automatic defender after the successful cell capture while N17 independently destroys any structure that would otherwise transfer. These effects operate on different capture consequences.

**Non-effects**

- N17 does not prevent the underlying cell from changing political ownership, change territorial progress, destroy structures on failed capture attempts, create ordinary combat-destruction rewards by implication, or destroy the holder's own structures when another faction is the captor.

**Resolved mechanic-definition result (#45)**

- N17 now consumes the generic structure-capture resolver rather than requiring a bespoke ownership mutation path. Capture disposition, transfer admission, typed capture consequences, atomic commit, and post-commit resolved-event semantics are canonical in `TERRAIN_AND_STRUCTURES.md`.

## N18 — I Have No Enemies

**Direct transformations / owners**

- Final territorial capture/settlement progress.
- For the N18 holder, final progress against **non-Fallout** target cells receives a structural `0.50×` post-multiplier.
- Fallout target cells are explicitly exempt from N18.

**Required seams / dependencies**

- `ordinary pressure-derived progress -> target base-terrain capture/settlement multiplier -> other explicit progress transforms -> N18 non-Fallout structural 0.50× -> deterministic stored progress` according to the canonical final-progress ordering.
- The rule applies to both hostile capture and neutral settlement because both use final capture/settlement progress.
- Target classification must use the current Fallout overlay state at the resolution point. Underlying terrain identity remains available for its ordinary terrain multiplier.
- If the target is Fallout, N18 contributes no multiplier at all; ordinary Fallout resistance and other rules still apply unless another trait transforms them.
- Partial-progress decay remains ordinary when positive advantage/progress is absent; N18 changes generated progress, not the decay constant.

**Explicit interactions**

- `N18 + P16`: explicitly canonical inversion. On Fallout, P16 removes the ordinary Fallout acquisition penalty while N18 is exempt; on non-Fallout, P16 is irrelevant and N18 halves final progress.
- `N18 + N05`: N05 hard-forbids Fallout acquisition, so N18's Fallout exemption cannot make those targets legal. Non-Fallout targets remain legal but slowed by N18.
- `N18 + P36`: P36 changes neutral-settlement Population **cost**, while N18 changes settlement **progress**. They compose independently; halving the Population cost does not remove the progress penalty.
- `N18 + P35/P44`: those traits can create Fallout that is exempt from N18 while the overlay exists; after the next successful capture removes Fallout, later acquisition of that cell again is non-Fallout and therefore subject to N18 when applicable.
- `N18 attacker -> P47 defender`: N18 may lengthen the time required to capture a non-Fallout Marsh cell, but once capture succeeds P47's separate post-capture casualty resolves normally.
- Terrain speed modifiers such as Plains/Highland/Mountain/Desert/Forest/Tundra/Marsh/Shallow Water remain ordinary preexisting progress inputs; representative projection tests should cover several values rather than pair-testing N18 against each terrain separately.

**Non-effects**

- N18 does not change attack/defense pressure, counter-response casualties, settlement Population cost, terrain identity, structure legality, movement, target ownership eligibility, or Fallout persistence.

# 3. Full-catalogue boundary conclusions

With P01–P54 and N01–N18 traced, the complete catalogue supports the following validation-domain boundaries:

1. **Spawn / pre-match initialization** — spawn profiles, exact origins, quota/geometry, starting ownership/Population, start-state grants, deterministic resolver/replay.
2. **Population state/accounting** — Capacity/Total/Available/committed Population, growth, peaks/entitlements, settlement costs/residuals, casualties/transfers, state-derived passive effects.
3. **Land combat / capture resolution** — source/target pressure, counter-response, acquisition progress, automatic defense, capture casualties, post-capture effects and structure-capture consequence dispatch.
4. **Terrain / territorial mutation** — terrain-effective classification, capture/settlement terrain modifiers, Fallout overlays, abandonment/neutralization, build eligibility.
5. **Persistent structures / transactions / admission / lifecycle** — purchase/upgrade/grant/capture admission, hard caps/prohibitions, provenance, active levels, effective fields, charge state, destruction/transfer.
6. **FFY economy / physical logistics** — source/event families, spatial/yield ordering, hard-zero rules, passive sources, Train/Trade lifecycle, piracy, explicit costs/losses.
7. **Naval / amphibious lifecycle** — Warship/Transport production and profiles, movement, rank/caps, repair, embark/landing/abort/destruction, Population carried by Transports.
8. **Strategic weapons / interception** — launcher legality, weapon access/cost, charge state, projectile/blast geometry, SAM interception and anti-ship behavior.
9. **Observation / concealment** — reveal/blackout/concealment geometry, lawful controller/AI projections, hostile-manifestation exceptions.

**Admission/legality is not a tenth generic gameplay domain.** It is an explicit validation stage inside every domain that owns an action capable of being prohibited/capped. N05, N06, N07, N09, N12, P11 and related traits prove that validators must distinguish:

```text
request/input
  -> canonical legality/admission
  -> effective transaction/profile
  -> authoritative resolution
  -> cross-system consequences
```

A hard prohibition/cap must fail at the legality/admission stage and cannot be bypassed by a later discount, zero-cost transform, grant path, geometry transform, or runtime effect.

# 4. Interaction-registry conclusions

The final explicit interaction registry should contain only combinations/dependencies where one trait changes state/geometry/value/legality that another trait directly consumes or where precedence must be proven. It should distinguish:

- **same-Origin same-axis composition** — e.g. P23+P42 range, P09+N10 Fort area;
- **same-Origin cross-axis/cross-system seams** — e.g. P37+N15 embark cost, P53+P20 persistent-Silo state;
- **hard-prohibition precedence** — e.g. N05 over P16, N12 over P42, N07 over structure creation paths;
- **cross-faction Origin interactions** — e.g. P44 attacker -> P48 defender, N18 attacker -> P47 defender;
- **external-system dependencies** — e.g. P19 -> Territorial Contact/Minor-Faction lifecycle, P08 -> canonical `atWar`;
- **generic representative composition suites** instead of pairwise explosion for unrelated modifiers that merely meet in a common aggregate, such as many ordinary offensive/defensive pressure sources.

The full registry should be derived from the completed trait traces after the blocker review, not by mechanically generating every legal trait pair.
